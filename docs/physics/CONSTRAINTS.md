# 履带物理硬约束与术语

更新时间：2026-10-26（S3.2 撤销边界与 AABB 阶梯坡术语修订）
状态：SBW 车型定义 + Bullet 物理架构规范。本文不是当前运行路径说明；当前接线见
[`CURRENT_WIRING.md`](CURRENT_WIRING.md)。旧方案归档见
[`LEGACY_CLEANUP.md`](LEGACY_CLEANUP.md)。

## 1. 不可违反的硬约束

### 1.1 仓库职责

1. KaguyaPyCore 只提供通用 Bullet 能力：物理线程、body/shape/joint 生命周期、
   通用动态履带运行段和不可变快照插值。
2. KaguyaPyCore 不实现车辆高度场、车型地形策略、爬坡规则、车型驱动、车辆渲染或
   Minecraft 车辆资源。
3. SuperbWarfare 负责全部车辆专用逻辑：车型编译、轮角色、质量、悬挂、张紧、
   驱动、差速、地形策略、生命周期、同步和渲染。
4. 车型专用数字只能出现在 SBW 车型数据或适配层，不能进入核心库分支。
5. 车型和悬挂数据以 SBW 自有定义为准：`TrackWheelRole`、`TrackWheelDefinition`、
   `TrackSuspensionDefinition`、`TrackSuspensionOverride`。MCSP 的
   `Suspension.Kind`、`carrier`、`hub`、`knuckle` 和 `spin` 只是行为参考，不是 SBW
   的字段或兼容层。
6. 核心库可以提供不含车型语义的 SI 弹簧—阻尼数学原语，但不能替车型决定载荷分配、
   轮角色或悬挂策略。

### 1.2 地形

1. 基础地形碰撞来自 Minecraft 方块 `VoxelShape` 转成的 AABB，包括完整方块、
   半砖、楼梯和多 AABB 形状。
2. 不使用全局平滑高度场替代方块碰撞，不使用 `LocalHeightField`、`TerrainSupportField`、
   `HEIGHT_FIELD` 或 `SUPPORT_PAIR` 作为车辆支撑。
3. 不使用探针扫掠承载、探针 miss 后高度场 fallback、固定楔面、按车长自适应坡长、
   人工抬升或直接 `setPos`。
4. 可选台阶辅助只能由 SBW 实现。它必须从真实方块 AABB 识别明确允许的低台阶，
   先关闭辅助验证基础 AABB 碰撞，再单独启用；辅助必须有高度、坡长和速度上限。
5. 辅助接触必须明确所有权，不能与原始方块碰撞在同一位置重复提供向上支撑；同一障碍
   不得被多个轮端或子步重复施加辅助。
6. 不得把两格墙或更高障碍削成可爬坡面。
7. 光滑连续斜坡不是方块 AABB。不得用高度场、固定楔面或探针把它补成“已测斜坡”。
   阶梯楔、楼梯和 AABB 阶梯坡就是 AABB 地形能提供的坡，属于 S3.1；光滑连续斜坡不属于门禁。
8. 辅助不能直接修改 body position、施加永久向上力，或把辅助效果写成悬挂行程。
   若采用接触响应，必须先在 Bullet 中证明时序；未证明前不得以 `setNormalWorldOnB`
   或未验证回调作为主方案。

### 1.3 真实机构

1. 导动轮、主动轮、负重轮、张紧器和履带运行段必须是明确机械角色；不能根据骨骼顺序猜测。
2. 只有负重轮使用独立悬挂。导动轮和主动轮是否可张紧必须由明确自由度定义。
3. 悬挂平移、轮端相对转动、传动轴和张紧自由度必须正交，不能争用同一自由度。
4. 独立悬挂是双向恢复机构：压缩时提供支撑，下垂时必须提供把轮拉回 bind pose 的
   恢复力。`MaxForce` 是力的绝对上限，不能把负向恢复力钳成零。
   可选 `Spring` / `Damper` 声明后必须进入实际力律；不得只改审计字段。有效频率必须
   由实际 `k/m` 推导，不能继续报告 authored 频率。
5. MCSP 传动响应层只限制目标速度生成，不得变成对车体、固定轮或关节的净力。
   `TractionLimit` 只能使用真实接触观测，且默认关闭。
6. bind pose 下悬挂关节两端 constraint frame 必须重合，零行程即 authored 轮位。
7. 物理履带运行段按**相邻轮对**组织：每个相邻轮对（含最后一轮回到第一轮）对应一个
   动态刚体，不是逐鞋销链。运行段数量由显式轮序决定，不由可见节距或 Z 排序推断。
8. 每个带内轮站恰好一个动态**轮端刚体**，同时承担轮端安装、轮形碰撞和轮质量。
   该刚体相对安装机构没有独立轮面自转自由度；可见轮面自转只服务渲染。
9. 运行段两端约束语义不同：第一端为轮心转动副（锁三平移、只放行轮轴转动）；
   第二端只锁运行段的法向平移，切向必须可滑。不得把第二端做成三平移全锁。
10. 运行段局部盒形在创建/恢复时确定；轮位、悬挂或地形变化不得导致逐步重建碰撞体。
11. 可见重复链节只是渲染模板，不是物理刚体。物理与可见表示共享轮序、wrap、半径、
    厚度和权威机构状态，但分别构建、分别更新。
12. 首轮允许通用有界轮带耦合，但必须有反作用、负载反馈、最大力矩和可测滑移。
13. 断带、脱轨、单轮损毁和修复首轮只预留接口。
14. 履带字段不得从 MCSP 整体照搬：它的 `linkPitch`、`sag`、`driveSlot`、
    `lateralFriction` 不在 `createBelt` 入参中，不能当作 native 物理入参，
    也不能为了对齐它们而在 SBW 数据里填造没有来源的值。其中 `driveSlot` 与
    `lateralFriction` 仍会经 carrier 元数据间接影响 native 驱动响应，不能写成
    “与物理无关”。

### 1.4 物理与渲染

1. 物理履带运行段决定承载、碰撞和驱动反作用。
2. 渲染器根据同步后的权威机构状态重建可见履带路径，按初始化时固定的链节数
   采样链节模板；间距随当前路径长度变化，不每帧重算数量。
3. 渲染结果不得写回物理 body、速度或位置。
4. 物理运行段数量、可见链节数量和模型动画骨骼数量分别记录，不能混用。
5. 客户端只消费不可变快照并插值，不独立模拟一套权威物理。
6. 物理与可见表示共享几何输入，但对象、碰撞和更新频率独立。

### 1.5 线程与生命周期

1. 每个 Minecraft Level 一个 Spark `PhysicsLevel` 和一个物理线程，固定 60 Hz，
   每个 Minecraft tick 三个 `1/60 s` 子步。
2. 只有对应物理线程可以创建、修改、加入、移除或销毁 Bullet body、shape 和 joint。
3. 物理线程不得直接读取 Minecraft 可变世界或实体状态；需要改世界的事件排回主线程。
4. 机构移除顺序：停止新任务 -> 移除/禁用 joint -> 移除 body -> 清理 owner 和缓存。
   关闭必须幂等。
5. 不得把地形未 ready 处理成永久运动学车体或永久清零速度。

### 1.6 参考证据边界

1. 反编译 Java 和 native 反汇编只能作为行为证据，不是原始 Rust 源码。
2. Rapier 的 API、单位和求解参数不能直接当作 Bullet 参数。
3. `BridgesSteps` 的 native 精确算法未恢复；只能把行为目标作为 SBW 独立验证的参考。
4. MCSP 的物理运行段与可见链节是两套对象；它们共享轮序、包络输入和机构状态，
   但分别构建、分别更新。具体 native 内部算法仍需 Bullet 原型验证。
5. MCSP 对履带字段组织、可见路径求解与 Java/native 运行段桥接有可逐行核对的源码贡献，
   不得概括为“仅一般行为参考”。但这不等于其车型 schema 或 native 拓扑可被整体复制。
6. 参考仓库与反汇编产物不进入代码提交；测试不得依赖本地
   `MCS_SOURCE_REVIEW/` 才能通过。

### 1.7 验收

1. 不通过放宽阈值、人工抬升、永久上升力、清零水平速度或加大全局阻尼掩盖问题。
2. 每次修复只改一个物理环节；先纯 JVM/原生测试，再 GameTest，再实机。
3. 自动测试通过不等于实机通过；每台车按计划暂停点由用户确认。
4. 未写入 [`ACCEPTANCE_LIMITS.md`](ACCEPTANCE_LIMITS.md) 的数字不能当作通过阈值。
5. 必须完成当前阶段退出条件，才允许进入下一阶段。
6. 已冻结的基线不得被直接覆写；修改必须追加 superseding 事件，
   并保留旧基线与旧成绩作为历史。当前的 B1 基线属于“当前版本自动通过”，
   不是永久批准，也不是实机通过。
7. 文档与 `MCS_SOURCE_REVIEW/` 不进入代码提交；代码提交必须能在不依赖
   本地参考检出的情况下独立构建和测试。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 物理履带运行段 | 相邻轮对之间的动态刚体、碰撞体和两端约束，承担履带载荷 |
| 轮端刚体 | 带内轮站唯一的动态刚体，承担安装、轮形碰撞和质量；无独立轮面自转 |
| 端约束 | 运行段与轮端的连接：第一端转动副，第二端单法向约束 |
| 包络输入 | 轮序、wrap、半径、厚度等物理与可见表示共用的几何数据 |
| 可见链节模板 | 按固定数量与当前间距重复用于渲染的链节几何，不参与物理求解 |
| 履带包络路径 | 根据轮心、半径和 wrap 方向求出的闭合路径，用于采样可见链节 |
| 普通地形 | Minecraft 方块 `VoxelShape` 转成的 AABB 静态碰撞 |
| AABB 阶梯坡 | 由真实方块碰撞盒逐级构成的可行驶坡；不是光滑高度场或固定楔面 |
| 台阶辅助 | SBW 可选策略，用于处理明确允许的低台阶；不是全局高度场 |
| 旧 `stepAssist` | 已撤销的 hull 法线改写/无界抬升实现，不得复活 |
| 接触所有权 | 标记某处向上支撑由原始地形、物理履带板还是辅助表面提供 |
| 导动轮 | 不接收驱动、承担导向的端轮；是否张紧由数据声明 |
| 主动轮 | 接收轮带耦合驱动的轮 |
| 负重轮 | 通过独立悬挂承载车体重量的道路轮 |
| 物理节距 | 仅旧鞋链拓扑使用的链节间距；轮对运行段不使用该概念 |
| 可见节距 | 渲染重复链节的间距；初始化时固定数量，间距随路径长度变化 |
| 批准 | 车型数据、几何、机构、测试和用户实机检查均满足阶段退出条件 |

## 3. 已撤销的旧方案

- KaguyaPyCore 高度场作为车辆唯一地面支撑：**撤销**。
- `LocalHeightField` 采样辅助和探针 fallback：**撤销**。
- 固定 `RUN_BLOCKS` 楔面、按车长自适应坡长：**撤销**。
- 探针承载、左右整体接触组和预处理整侧悬挂高度：**撤销**。
- 旧 `VehicleBody.stepAssist`（hull 接触法线改写、`setNormalWorldOnB`、无界/永久向上力、
  逐轮重复 lift）和直接位置修正：**撤销**。
- **仍有效：** S3.2 的 `TrackedStepAssist` 受限辅助目标；撤销不等于取消可选台阶辅助。
- 可见链节作为物理刚体或物理运行段与模型链节一一绑定：**撤销**。
- 逐鞋销链作为唯一物理拓扑：**撤销**；改为相邻轮对运行段。旧鞋链实现与成绩保留为历史。

当前旧调用点仍可能存在，见 [`CURRENT_WIRING.md`](CURRENT_WIRING.md)。撤销决定不等于
代码已经删除。

## 履带地形新增硬约束（2026-10-28）

- 履带地形几何只能来自 `TerrainRegionSnapshot`。采样与构建路径不得出现 `Level`、
  `LevelChunk`、`BlockState`、`VoxelShape`。
- `snapshotRegion` 的 `Missing` 只能导致等待：不得用部分区域建 mesh，也不得回退到方块 AABB。
- 采样窗口由 `TerrainEnvelope` 决定；`WindowRadius` 只能是上界，不得再作为覆盖依据。
- 车辆必须每 tick 用 `requestRegion` 续期自己的区域；履带刚体不在 Core 激活查询里。
- mesh 安装必须校验 `requestId` 与 `runtimeGeneration`，且不得让 `installedRequestId` 回退。
- 地形等待禁止把 dynamic 刚体改成 kinematic；只允许 factor lock。
- planner 必须输出六面外壳并按区间包含关系消除内部面；暴露的桥面底面必须保留。
