# 交接文档（first to do）

更新时间：2026-11-01  
性质：下一阶段实施计划；不是实现完成或验收通过的证明。

## 1. 目标

将 99A 每侧现有履带下部改成固定数量的独立刚性履带板：每个负重轮正下方一块，相邻负重轮之间再一块。若一侧有 `N` 个负重轮，下部物理板数必须为 `2N-1`；99A 当前每侧 6 个负重轮，因此每侧 11 块。

每块板本身保持刚性，整体只在相邻板的连接处弯折。前后斜段、导动轮和主动轮的包绕、顶部回程沿用现有方案。悬挂继续按 SBW 自己的车型定义工作。此次不改驱动控制、差速、摩擦参数或既有驱动断言。

## 2. 已确认的依据与边界

- MCSP 每次插入一个 RUN 会创建动态刚体和碰撞体，并在两端连接；没有证据表明一个 RUN 会在自身内部弯折。因此本方案中的每块 SBW 履带板都是独立刚性物体，只能在板与板的连接处弯折。
- `2N-1` 是本项目指定的下部布局，不是 MCSP 的原有板数或拓扑。MCSP 仅作为“刚性板有实体碰撞、整体靠连接改变形状”的行为参考。
- 每个负重轮只对应自己正下方的一块轮下板。板间连接负责相邻板的连接，不得另外固定到负重轮或限制负重轮的悬挂行程。
- 正常受力路径应能从地面履带板，经板间连接及轮下板与轮体的支撑连接，再经该轮自己的悬挂传到车体。不能只凭关节配置推断承载正确，必须用原生物理测试量测。
- 履带上部和包绕段、张紧方式、接触驱动登记及质量总额不得因下部重排而无意改变。
- 不使用人工抬升、位置修正、探针补偿或虚拟地面来帮助新履带贴地。

## 3. 当前工作树基线

- 仓库：`SuperbWarfare`；分支 `Physic-Update`；HEAD `86466a79d7`。工作树有大量未提交修改，目标定义、编译器、运行时、99A 数据、模型、测试和文档都已有用户改动。实施时逐文件增量审阅，不覆盖、不清理这些改动。
- 当前生产拓扑仍为 `EnvelopeBelt`：底部从一整块刚体开始，由地形检测动态拆分、移动和合并；上部和绕轮由现有包络刚体及轮体上的包角形状承担。
- 当前 `TrackedDynamicBelt.wheelLock()` 只为负重轮添加单向法向限位，其余平移和角向自由度由现有关节配置处理。注释和实际轴配置必须一起复核，不能仅凭注释认定侧向、纵向和法向行为正确。
- 当前负重轮悬挂由车体到轮端的独立安装关节控制；`EnvelopeBelt` 路径把普通弹簧和平均阻尼放在安装关节中，渐进缓冲块残差另行处理。新板不得再建立一组约束来锁住相同的竖直行程，也不得同时重复施加同一普通弹簧和阻尼。
- 当前 99A JSON 的 `Track.Pitch` 为 `0.23307 m`，是可见链节节距，不是已确认的物理轮下板长度。当前工作树还把每侧 `RunMassBudgetKg` 写为 `5688 kg`，并修改了模型与轮骨骼绑定；实现必须以届时审阅过的工作树数据为准，保留其质量核算，不能恢复旧数值或静默重分配。
- 最近交接的已知结果：坡面 wheel-lock 法向残差约 `5.18 mm`，仍未通过；左右转向 GameTest 的偏航约 `0.002–0.003 rad`，原 `0.1 rad` 断言未通过。两者是本轮开始前的基线问题。不得调宽断言、改摩擦或改驱动来掩盖它们。

## 4. 实施前门槛：确定板尺寸

目前车型定义没有轮下板或轮间板的物理长度字段。开始装配新板前，先从当前 99A 模型、履带实体几何和轮位中查明可追溯的长度来源：

1. 确认模型单位、渲染缩放、底部路径方向和每个负重轮的实际接触位置；使用已经编译的负重轮顺序与 `roadFeet`，不按骨骼名字猜轮序。
2. 查找模型里是否存在可明确代表轮下物理板边界的几何。可见链节模板只有在证明它确实描述该物理板长度后才可作尺寸来源。
3. 若模型没有唯一尺寸，向用户确认轮下板长度或明确的尺寸规则。不得用 `Track.Pitch`、车轮半径或“看起来合适”的比例自行代替。
4. 轮间板长度按相邻轮下板端点之间的剩余底部路径长度计算；板长必须为正，板序无缺口、无重叠，且两端能与保留的前后斜段连接。若轮位或尺寸使条件不成立，编译失败并报告具体轮对，不作隐式缩放或平移。
5. 将最终采用的物理尺寸写进通用车型数据字段并补充校验；记录数据与模型哈希。字段名称和单位在尺寸来源确定后再定，不提前固化猜测值。

**阻塞规则：** 若从当前几何不能唯一得出尺寸，就暂停运行时装配和 99A 数据切换，只完成尺寸审计并取得用户确认。

## 5. 目标布局与质量

按下部路径顺序生成：

```text
前斜段 -> 轮下板 1 -> 轮间板 1 -> 轮下板 2 -> ...
        -> 轮间板 N-1 -> 轮下板 N -> 后斜段
```

- `N` 个轮下板与 `N-1` 个轮间板各自是独立动态刚体，各有自己的实体碰撞体；不能把多个板合成会弯曲的一体刚体。
- 每个轮下板记录唯一的 `wheelIndex`。轮间板不拥有负重轮，也不与负重轮建立额外连接。
- 所有板的宽度、厚度和碰撞余量沿用经过审计的现有履带数据；长度来自第 4 节确认的物理尺寸。
- 依据实际材料长度分配板质量。新旧底部表示的总材料质量必须一致；加上保留的前后斜段和顶部自由段后，每侧履带总质量必须等于当前车型数据声明的预算，整车总质量仍闭合。包角仍属于现有轮体形状，不重复计入履带板质量。
- 每块板独立计算盒体惯量；如果需要调整转动惯量，只记录为有依据的物理参数，不改变质量或静态承载。

## 6. 板间连接与悬挂分工

### 板与板

- 相邻下部板在共享端销点连接。连接锁住销点的三向分离，只允许绕履带横向轴转动；弯折角限制沿用当前已声明的履带限制，不能在实现中另设未审定的更宽角度。
- 轮下板—轮间板及轮间板—轮下板都使用同一套连接语义。最前和最后的下部板分别接回既有前、后斜段。
- 保留上部连接、绕轮包角、主动轮处滑动和现有张紧弹簧。不能让新板间连接跨过保留的滑动位置或把张紧行程锁死。
- 创建、重建和销点位置都经 `RuntimeBeltWorld` 与现有装配回滚账本管理；移除关节先于刚体，失败时完整回滚。

### 轮下板与负重轮

- 每个负重轮只与编号相同的轮下板建立支撑关系。该连接允许履带纵向滑动和轮体离开履带，只提供经测试确认必要的单向法向支撑；不得把轮固定在板上。
- 重新推导 Bullet 关节 frame 的局部轴方向，核对当前 `wheelLock()` 的代码轴与注释。履带横向定位若需要约束，必须只约束侧向，不能占用竖直悬挂行程；不得增加第二个纵向止挡。
- 车体到负重轮的原独立悬挂安装关节继续独自决定轮的上下行程、限位和普通弹簧/阻尼。板间销接不能连接回车体，也不能重复限制这段行程。
- 参考 MCSP 时只采用可核实的行为：独立悬挂、行程边界、弹簧和阻尼各有明确作用。SBW 继续使用自己的悬挂定义，不引入 MCSP 的车型字段或轮端对象名称。
- 确认普通弹簧/阻尼只由一个位置承担：当前安装关节弹簧路径与显式悬挂力不能重复计算。分别验证压缩支撑、下垂回弹、阻尼方向和渐进缓冲块；`MaxForce` 正负方向语义不变。

### 地面接触和载荷

- 新履带板必须接触地形，并通过当前统一的履带碰撞、接触登记和生命周期入口进入物理世界。
- 单独测试“履带板接地”和“轮体接地”，量测各自法向接触与悬挂行程，再测试生产碰撞过滤下的组合情况。若轮和板在同一接触位置重复提供向上支撑，先明确接触所有权并修正碰撞过滤；不得把两份支撑误报成悬挂承载改善。
- 通过冲量、轮位、悬挂行程和车体响应证明完整路径；关节 `appliedImpulse` 不作为载荷读数。

## 7. 代码实施顺序

仅在板尺寸门槛通过后实施；按小步提交式审阅，不覆盖其他工作树改动。

1. **车型数据和编译结构**
   - 在 `TrackedDefinitions.kt` 为下部固定板布局及经确认的尺寸增加通用定义和字段校验。
   - 在 `TrackedSpec.kt` 表达每块板的类别、中心、方向、长度、质量、销点和唯一负重轮归属。
   - 在 `TrackedEnvelopeBelt.kt` 编译 `2N-1` 的固定布局，复用编译后的负重轮顺序和 `roadFeet`，并验证前后端衔接、正长度、质量守恒和销点连续。
   - 在 `TrackedVehicleCompiler.kt` 接入新编译结果；错误的尺寸或布局不得生成可用车辆规格。保留其他拓扑和旧数据的行为。

2. **物理刚体与销接**
   - 在 `TrackedDynamicBelt.kt` 增加固定下部板的创建和摆放；每板独立刚体/碰撞体，板内不变形。
   - 为每对相邻下部板建立横向销接；将首尾接回现有斜段。前后段、顶部、包角和张紧方式保持现状。
   - 固定板布局不调用按地形拆分、移动或合并的旧 `updateSegmentation()` / `repartition()`；旧逻辑仅在仍有车型使用旧表示时保留，不误伤其他拓扑。
   - 保证建造、重建、销点重绑和关闭均正确登记、回滚和清理。

3. **悬挂与运行时接线**
   - 在 `TrackedVehicleRuntime.kt` 仅为新下部拓扑关闭旧底部动态拆合调度；继续使用现有地形碰撞、接触登记、悬挂弹簧和账本接口。
   - 每个负重轮的支撑连接只绑定其轮下板。检查局部坐标轴、单向法向方向和侧向定位，不以轮间板建立第二套轮支撑。
   - 按第 6 节选择并验证地面接触所有权。新板仍通过既有履带接触入口参与物理接触；不得改动 `TrackedDriveController`、`TrackedContactDrive`、`applyDrive()`、`applyBeltContact()` 的控制律或数值。

4. **状态与渲染**
   - 物理快照按真实板端销点和现有上部/包绕路径输出连续履带中心线；插值和可见链节仍是渲染数据，不写回物理。
   - 固定下部板的数量在同一车型配置下保持 `2N-1`，不随地形改变。检查包绕区与上下段连接处无渲染断口；不把可见链节数量当作物理板数量。

5. **测试、记录和状态**
   - 先 T0，再 T1，再 99A T3；需要客户端视觉的内容最后做 T4。每一阶段失败先定位，不跳过门槛。
   - 新拓扑、负重轮安装 frame 或悬挂载荷路径改变会重开相关悬挂/运行段基线。保留旧结果，追加新结果；仅在对应限值已冻结时标记自动通过。
   - 更新 `docs/physics/HANDOFF.md`、`STATUS.md`、必要的决策/测试文档及 `records/events.jsonl`。事件追加而非改写；执行 `node docs/physics/records/validate-events.mjs`。MCP 当前未配置时如实记为 unavailable。

## 8. 验证门槛

### T0：数据和几何

- 2 轮诊断布局产生 3 块下部板；99A 每侧 6 个负重轮产生 11 块；布局严格交替且负重轮顺序与编译顺序一致。
- 每个轮下板恰有一个对应轮号，轮间板没有轮号；不存在重复支撑、零长度、负长度、缺口或重叠。
- 所有相邻板共享销点；销轴为履带横向，单块板几何保持刚性；首尾与保留斜段准确相接。
- 单侧各履带板和保留履带段质量之和等于数据预算，整车质量核算闭合。
- 尺寸来源、模型和数据哈希可追溯；无尺寸来源的输入编译失败。

### T1：原生 Bullet 机构

- 使用生产创建路径、真实动态负重轮和生产悬挂装配，不用运动学轮代替验收。
- 对板施加外力后，相邻板可在销处转动，销点不脱开；销转角受限；单块板不弯曲。
- 逐个负重轮测试其只由正下方轮下板支撑；相邻轮悬挂可以独立压缩和回弹，轮下板连接不夹住安装关节行程。
- 验证安装关节的弹簧静载、正负恢复方向、阻尼耗散、行程限位和缓冲块；确认没有普通弹簧/阻尼重复施加。
- 分别记录板—地形、轮—地形和生产组合碰撞下的接触数、法向冲量、轮位与悬挂行程，检查重复向上承载。
- 检查平地与阶梯坡静态装配、销点误差、轮板接触、悬挂载荷路径、碰撞过滤、休眠/唤醒、重建和销体清理。

### T3：99A 服务端 GameTest

- 覆盖平地静置、各负重轮压缩/回弹、AABB 台阶或阶梯坡上的板间弯折，以及实体卸载/关闭。
- 核对每侧固定 11 块下部板，生产地形接触归属正确，悬挂未被锁死，车体没有由重复接触抬升。
- 运行直行、制动和转向现有用例作为回归；不改驱动实现、摩擦、差速、控制目标或断言。当前已知左右转向失败单独标记，不得归因或算作本次履带通过。
- 未冻结的销点间隙、轮行程波动等只记录实测值，不自创通过阈值。保留并报告现有坡面约 `5.18 mm` 法向残差基线，不能预先当作通过。

### T4：客户端检查

- 观察可见履带是否跟随权威物理中心线，固定板数量变化不会造成模型渲染跳变或路径断口。
- 确认渲染插值不改变服务端物理状态，不新增客户端独立物理。

## 9. 明确不做的事

- 不改变驱动、差速、接触驱动律、摩擦系数、速度目标或既有断言。
- 不让一块物理板内部弯折，不把 `2N-1` 的 SBW 下部布局说成 MCSP 原有拓扑。
- 不改前后斜段、绕轮包角、顶部回程和张紧方案，除非测试证明新下部接口无法连接；若触及这些边界，先暂停并记录原因。
- 不为通过测试而删除用户已有修改、放宽限值、加入探针支撑或人工位置修正。
- 不在尺寸未核定、T0/T1 未完成或载荷路径未证明前声称 99A 新履带已通过或已批准。
