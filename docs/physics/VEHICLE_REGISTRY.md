# 车型注册、批准和常规获取

更新时间：2026-10-22

## 1. 三种状态必须分离

| 状态 | 含义 |
|---|---|
| Registered | 有通用实体/数据/模型适配描述，可以被编译器看到 |
| Approved | 通过规定的自动测试和用户实机暂停点，可以进入新物理运行路径 |
| NormallyAvailable | 会出现在创造栏、容器、配方或普通获取入口 |

第一阶段只有 `ztz_99a` 具备新履带物理批准和常规获取资格，它是**第一辆正向接入并验收的
履带载具**。其他车型可 Registered，也可被命令或旧存档加载用于开发，但不自动变成
Approved 或 NormallyAvailable。轮式车辆不在本轮范围内，allowlist 保持为空。

## 2. 通用注册接口职责

注册接口只描述：

- 稳定车型 ID；
- 来源（内置、数据包、附属模组）；
- 模型资源和数据定义；
- 通用机构角色和参数；
- 适配器版本和审计备注。

注册接口不得携带“该车型专用求解函数”。如果数据无法表达某个机械特性，应扩展通用能力
和数据 schema，而不是添加车型 if/else。

## 3. 注册顺序

```text
实体/适配器注册
 -> 数据资源加载
 -> 车型 ID 合并和重复检查
 -> 模型/数据编译
 -> 轮角色、物理运行段和质量审计
 -> approved 状态由阶段证据更新
 -> 常规获取入口按 NormallyAvailable 过滤
```

数据 reload 后必须使旧编译缓存失效；缓存键至少包含车型 ID、机构数据哈希、模型哈希
和编译器/规范版本。

## 5. 附属模组

允许附属模组显式注册新车型，但必须：

1. 使用公开的通用机构、TrackRun 和插值接口；
2. 提供模型/机构数据和哈希；
3. 通过结构、静载、驱动、地形、生命周期、渲染和实机（若属于本项目发布范围）阶段；
4. 不把测试客户端、下载脚本或运行存档作为注册依赖提交。

附属模组不能依赖 KaguyaPyCore 的高度场或旧探针接口，因为这些接口不再提供。
