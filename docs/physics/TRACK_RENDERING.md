# MCSP 风格履带渲染

更新时间：2026-10-23（轮对运行段定稿）  
状态：渲染设计基线；R1 实现，尚未开始  
对应物理文档：[`ARCHITECTURE.md`](ARCHITECTURE.md)、
[`CORE_API_CONTRACT.md`](CORE_API_CONTRACT.md)

## 1. 目标

按 MCSP 的方式渲染履带：

- 物理运行段与可见重复链节是两套对象，但共享包络输入与权威机构状态。
- 根据同步后的机构状态重建闭合履带路径。
- 可见链节数在初始化时固定，间距随当前路径长度分配。
- 渲染不创建物理 body，不写回物理状态。

## 2. 输入

来自 KaguyaPyCore 的不可变快照：

- 车体 pose 和速度。
- 轮端位置、悬挂行程、张紧行程。
- TrackRun 物理状态摘要。
- 左右履带带速、相位和驱动状态。
- physics frame 和时间戳。

来自 SBW 车型数据：

- 轮序和逐轮 wrap。
- 轮半径、宽度和履带厚度。
- 链节模板与可见节距来源。
- 模型骨骼绑定。
- 材质和动画参数。

**字段来源边界（必须先读）：**

| 字段 | 现状 | 约束 |
|---|---|---|
| 逐轮 `wrap` | 当前车型数据无此字段 | 必须显式声明；R1 实现前不得默认猜测 |
| 可见节距 | 模板纵向长度 `0.23307 m` 是**有来源的候选** | 是否采用该派生规则仍待确认；不得用物理节距或“长度÷骨骼数”冒充 |
| 可见下垂 `sag` | 当前无字段 | MCSP 的 `sag` 是可见路径参数；本项目尚未确定是否需要、取值多少。禁止凭空填数 |
| 轮宽/厚度 | 已有（来自模型模板） | 渲染侧可直接用，但不能反向覆盖物理形状 |

对比 MCSP 的分层说明见
[`MCSP_BULLET_MAPPING.md`](MCSP_BULLET_MAPPING.md) §2.4 与 §3.1：可见路径侧确实消费
`linkPitch`/`sag`，但这些不是 native 物理运行段的输入。

## 3. 路径重建

参考 `PlatformGearDraw` 的 `solve`：

1. 读取每个轮的同步后轮心。
2. 读取接触半径和履带厚度。
3. 按轮序和 inside/outside wrap 建立圆包络。
4. 求相邻圆之间的外公切线或内公切线。
5. 连接圆弧和切线，形成闭合路径。
6. 计算总长度和闭合误差。

路径求解必须是 SBW 的纯数学实现，不访问 Bullet，不读取 Minecraft 世界。

**注意：** MCSP 渲染器由同步的悬挂状态重建路径，**不读取 native 运行段的逐段 pose**。
SBW 必须采用同一关系，不得让渲染路径反推或修正物理姿态。

## 4. 链节采样

参考 `PlatformGearDraw.link`：

```text
count = max(1, ceil(restLength / visiblePitch - 0.001))   // 初始化时固定
restPitch = restLength / count                             // 初始化时固定，之后不再改
currentSpacing = currentLength / count                     // 每帧随路径长度变化
sampleDistance = phase * restPitch + linkIndex * currentSpacing
point = path.pointAt(sampleDistance)
tangent = path.tangentAt(sampleDistance)
rotation = atan2(tangent)
```

关键区分：**`restPitch` 是初始化常量，`currentSpacing` 才是每帧变化的间距。**
把两者混为一个变量会让相位推进速度随悬挂行程漂移，链节在路径伸缩时看起来忽快忽慢。

输出：

- 可见链节位置。
- 切线旋转。
- 可选法向偏移。
- 链节索引。

**可见链节数量不是每帧用 `round(pathLength / pitch)` 重算。** 数量在初始化时固定，
这样悬挂行程变化只改变间距，不改变链节总数，也不会出现链节突然增删。

物理运行段数量由显式轮序决定，两者独立。

## 5. 相位

- 相位来自权威带速（驱动 slot 的带面速度），不由纯车体速度单独推算。
- 相位按**固定的 `restPitch`** 推进：`phase += dir * beltSpeed * dt / restPitch`，以链节数为周期环绕。
- 左右履带独立相位。
- 倒车时相位反向。
- 相位环绕使用周期最短路径插值。
- 客户端只对权威快照插值，不独立模拟驱动力。

## 6. 骨骼和模板

- 履带根骨骼的悬挂偏移只应用一次。
- 子骨骼不重复叠加同一悬挂高度。
- 可见链节模板按车型模型定义重复。
- Bedrock 和 Geckolib 使用同一路径结果，只做绑定适配。
- 物理运行段不直接绑定模型骨骼。
- 轮 ID 从编译绑定取，不从骨骼名数字猜测。

## 7. 禁止事项

- 不用 `TrackAnimationProfile` 预处理曲线作为新履带位置来源。
- 不用整侧统一高度代替逐轮路径。
- 不创建每个可见链节的 Bullet body。
- 不在渲染线程读取 native Bullet body。
- 不把客户端渲染结果写回服务端物理。
- 不让物理运行段数和可见链节数隐式相等。
- 不每帧重算可见链节数量。

## 8. 测试

### T0 纯数学

- 两轮圆包络。
- 多轮闭合。
- inside/outside wrap。
- 相位环绕和倒车。
- 左右独立。
- 悬挂变化后路径连续。
- 可见数量初始化固定、间距随长度变化。
- 带速与车体速度分离。

注意：上述 T0 用例属于 R1，当前尚未实现。
`TEST_MATRIX.md` §4 已把它们列为计划项，不得因为文档存在而标为通过。

### T4 渲染

- Bedrock 模型。
- Geckolib 模型。
- 静止、前进、倒车。
- 原地转向。
- 单侧压坡。
- 网络延迟和物理帧丢失。
- 长时间行驶无漂移和分离。

## 9. 退出条件

- 可见履带路径与权威机构状态一致。
- 可见表示不参与求解，且与物理共享包络输入。
- 物理运行段数、可见链节数和动画骨骼数分别记录。
- 用户实机暂停点 D 确认渲染和长时间稳定。
