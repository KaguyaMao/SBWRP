更新时间：2026-10-19

## 0. 阶段规则

- 每个子阶段只解决一个层次的问题；不以调参掩盖契约错误。
- 硬约束要求必须完成当前阶段才允许进入下一阶段。完成与否只按本文件该阶段的退出条件判断。
- 用户窗口分两类，状态不能混用。P0–P3 是证据确认门：用户确认文档或自动测试证据后才能进入下一阶段，但这不是实机通过，不能标 `manual_passed` 或 `approved`。P4–P7 的 A–D 和 P8 的每车确认才是游戏内实机暂停点。
- 没有对应窗口的用户确认，不能进入下一阶段或下一车型。
- 新架构中高度场是唯一地面支撑来源。旧探针、楔面、坡长自适应和人工抬升不得重新接回。
- 所有阶段均记录代码提交、数据/模型哈希、测试命令、测试结果、失败现场和人工结论。
- 代码、测试源码和架构文档可入库；运行实例、存档、构建产物、日志、测试客户端/服务端
  和其启动/下载/设备脚本禁止入库。

## 3. P2：通用独立悬挂与闭链机构基础

### P2.1 悬挂语义

- 对照 Machine-Max 的独立轮结构，确认 `New6Dof`/底层 spring 版本的单位和阻尼语义。
- 不把旧 `SixDofSpringJoint` 的参数语义未经证明地当作 `New6Dof` SI 参数。
- 通过原生测试验证静载、预载、压缩/回弹阻尼、行程限位和自由滚动。

### P2.2 轮角色和自由度

- 负重轮：平动悬挂 + 自由滚动轴。
- 主动轮：驱动耦合 + 必要的导向/轴约束。
- 导动轮：导向和/或张紧自由度由数据明确声明。
- 张紧力方向必须与允许的机械自由度一致，禁止“轴锁死后沿锁轴施力”。

### P2.3 闭链静态机制

- 用真实板形状、销轴、节距和板姿态建立闭链。
- 修正当前板形状只使用 AABB Box、板横向位置取第一轮、装配偏移未应用等问题。
- 测量闭合误差、相邻 pin 距离、关节角、轮板间隙、穿透和长期漂移。

### P2 退出条件

- 单轮、单侧闭链、双侧闭链测试全通过。
- 真实履带板承担负重，不能由测试夹具地面或虚拟整侧板承担。
- 负重轮悬挂和履带滚动自由度没有同轴约束冲突。
- **证据确认门 P2：** 用户确认原生机构证据后才能把 99A 数据审计当作可进入游戏接线的前提。

## 4. P3：ZTZ-99A 几何与数据审计

### P3.1 数据冻结

- 记录 99A 机构 JSON 和模型 JSON 的 SHA-256。
- 复核每侧 1 导轮、6 负重轮、1 主动轮；高度差和横向位置必须以物理数据为准。
- 明确 `ChassisOrigin`、Bullet body origin、模型 pivot 和轮心坐标的转换。

### P3.2 单板模型适配

- 允许每侧 78 块物理板，不受旧模型每侧 37 个动画骨骼限制。
- 物理单板、销轴和导向结构可以使用独立适配形状；可见模型保留车型尺寸和外观。
- 物理节数、渲染节数和旧动画骨骼数分别记录，不混用。

### P3.3 质量预算

- 车体、轮、履带板和炮塔质量总和必须等于车型质量。
- 负重轮承载质量、板质量、车体簧载质量分别输出审计值。
- 不沿用旧 `TrackSupportMassFraction` 或探针预留质量。

### P3 退出条件

- 99A 编译审计无坐标契约错误、无角色错误、无闭链错误和质量预算错误。
- 纯 JVM 机构测试通过后才允许进入游戏接线。
- **证据确认门 P3：** 用户确认 99A 几何、质量和闭链审计后才能进入 P4。确认不等于常规获取批准。

## 5. P4：99A 游戏生命周期接线

### P4.1 注册和批准

- `TrackedVehicleRegistry` 接入资源加载和数据 reload，缓存键包含模型/机构/编译器版本。
- 99A 标记为第一阶段唯一 approved tracked vehicle。
- 其他车型可保留注册数据，但不进入常规获取和新物理批准列表。
- 附属模组可显式注册新 ID，仍必须经过通用编译和批准。

### P4.2 创建、更新、关闭

- 在 `VehiclePhysics`/`VehicleBody` 创建真实 `TrackedMechanismRuntime`。
- 所有 Bullet 对象设置 owner，走 Spark 的 add/remove joint/body 队列。
- Entity unload、chunk unload、Level unload、NBT reload 和 reset 均有闭链清理顺序。
- 无旧探针承载、无旧整侧力、无固定楔面支撑。

### P4.3 高度场接线

- 99A 的履带板和车体都只从高度场得到地面支撑判定。
- 原始 terrain 只能作为结构障碍，经接触仲裁避免重复向上承载。
- 高度场未 ready 时是“无有效支撑”，不能替换成旧探针或假地面。

### P4 退出条件

- 99A 可生成、静置、移除、重载和卸载，无幽灵 body/joint。
- 真实履带板 -> 负重轮 -> 悬挂 -> 车体的静载路径可测。
- **实机暂停点 A：** 用户检查轮位、轮板间隙、板闭合、导轮高度、张紧方向和静置姿态。

## 6. P5：99A 驱动与差速

### P5.1 通用轮带耦合

- 以主动轮/履带板相对运动为输入，施加有界扭矩/切向力。
- 保留反作用、负载反馈、滑移、制动和滚阻；不直接设置车体或板速度。
- 记录每侧目标带速、实际带速、主动轮角速度、滑移和接地法向载荷。

### P5.2 差速

- 右转左侧更快、右侧更慢；左转相反。
- 直行、倒车、原地左右转、行进转弯、释放油门和制动分别测试。
- 不用求解后直接限制偏航速度作为主要转向机制；任何控制限速只作为明确的稳定性保护。

### P5 退出条件

- 自动测试通过直行/倒车/制动/左右差速方向和负载反馈。
- 低速和高附着条件下无 relay chatter、无突然角速度尖峰。
- **实机暂停点 B：** 用户检查操控方向、加速、制动、原地转向和声音/视觉相位。

## 7. P6：99A 高度场越障

### P6.1 基础表面

- 平地、真实斜坡、单格高度差、连续楼梯、侧向高度差。
- 高度场接触点和法线可视化；确认没有探针、楔面或人工抬升。

### P6.2 边界

- 两格墙拒绝；连续高墙拒绝；洞和未知区块失去支撑。
- 桥面/桥下、多层表面、section 边界、区块加载/卸载。
- 斜向接近、倒车接近、单侧履带悬空和一侧挖空。

### P6 退出条件

- 所有支撑来自高度场，支撑载荷通过动态履带板和机构传到车体。
- 任意旧楔面/探针/step assist 关闭后仍满足验收。
- **实机暂停点 C：** 用户检查坡面、楼梯、台阶、墙拒绝、挖空和履带贴地表现。

## 8. P7：99A 同步、渲染和性能

### P7.1 状态同步

- 服务端权威；客户端接收车体姿态、轮/板/履带状态和必要的高度场版本/诊断摘要。
- 不新增每块板的网络实体；客户端按服务端快照和本地渲染数据生成可见履带。
- 客户端不得用旧预处理轨迹覆盖真实板/轮姿态。

### P7.2 性能

- 先测 1 台活动 99A：物理子步耗时、创建/销毁、接触数量、快照延迟、丢帧和内存。
- 再测 4 台活动车：包含地形重建、休眠/唤醒、网络同步和区块边界。
- trace 日志不得作为性能基准；记录无 trace 的重复测量。

### P7 退出条件

- 单车和四车达到事先批准的预算；若超预算，先做通用优化，不删减物理正确性。
- **实机暂停点 D：** 用户检查低速/高速、悬挂回弹、落地、转向、渲染和长时间稳定。

## 9. P8：其他履带车型逐车迁移

每台车独立完成以下小阶段，不能以 99A 的通过替代：

```text
车型数据/模型审计
 -> 纯编译与闭链审计
 -> 单侧/双侧静载
 -> 游戏生命周期
 -> 驱动差速
 -> 高度场越障
 -> 性能
 -> 用户实机确认
 -> 批准常规获取
```

推荐顺序：`BMP-2 -> Bradley -> T-90A -> PLZ-05 -> M1A2 -> YX-100 -> Prism Tank`。
YX-100 和 Prism Tank 即使完成数据审计，也不会在 99A 阶段自动开放。
