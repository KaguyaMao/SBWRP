# 履带物理硬约束与术语

更新时间：2026-10-19  
状态：新架构规范。本文不是当前运行路径的实现说明；当前接线见 [`CURRENT_WIRING.md`](CURRENT_WIRING.md)

## 1. 不可违反的硬约束

### 1.1 物理来源

1. 已批准履带车的姿态、重力、碰撞、支撑、悬挂、履带板约束和驱动反作用必须来自
   Spark/Bullet 物理系统。
2. Minecraft 主线程只负责复制普通值、提交命令、消费不可变快照和执行游戏规则；不得
   在实体 tick 中再次写入由 Bullet 管理的车辆位置、速度或姿态。
3. 高度场是履带车地面支撑及地面接触判定的唯一来源。不能并行使用旧探针、固定坡道、
   原始方块顶面冲量或人工向上力来托住车辆。
4. 高度场不允许凭空填洞、不允许跨越未知区块、不允许把两格墙或更高障碍削成可爬坡面。
5. 高度场平滑只允许有限的向下修正；下削量、作用范围、坡度和有效表面类别必须有
   显式边界，不能因为测试失败不断放大。
6. 履带板、轮组和车体共享同一版本的高度场表面。不能每个履带板自行读取 Level 或
   使用不同版本的地形数据。

### 1.2 真实机构

1. 导动轮、主动轮、负重轮、张紧器和履带板必须是明确的机械角色；不能根据骨骼顺序
   或“前后轮”猜测角色。
2. 只有负重轮使用独立轮悬挂。导动轮和主动轮是否可纵向张紧，必须由明确自由度定义，
   不能用锁死轴后再施加同轴方向的力。
3. 履带板是动态 Bullet 刚体组成的闭合销链；固定节距、闭合误差、销轴位置和关节角
   必须经过静态审计。
4. 负重轮的滚动自由度不能同时被悬挂关节和履带传动关节争夺。悬挂自由度、滚动轴和
   张紧自由度必须正交。
5. 首轮允许使用通用的有界轮带耦合传递驱动力，不要求首轮制作真实主动轮齿；但耦合
   必须有负载反馈、反作用、最大力矩和可测滑移，不能直接推动车体或直接写速度。
6. 断带、脱轨、单轮损毁和修复首轮只预留拓扑与生命周期接口，不纳入首轮玩法验收。

### 1.3 通用化

1. 入口必须是“通用注册/API/编译/求解器 -> 车型数据与适配层精调”。
2. 禁止为单车写物理算法分支。ZTZ-99A 的特殊数字只能在车型数据或适配描述中出现。
3. 允许附属模组显式注册新车型，但新车型必须使用通用机制并经过独立批准和逐车验收。
4. 物理批准状态与常规获取状态分离：第一阶段常规入口只开放 99A；命令和旧存档仍可
   用于开发测试，不代表其他车型已通过验收。

### 1.4 线程与生命周期

1. 每个 Minecraft Level 一个 Spark `PhysicsLevel` 和一个物理线程，固定 60 Hz，每个
   Minecraft tick 三个 `1/60 s` 子步。
2. 只有对应物理线程可以创建、修改、加入、移除或销毁 Bullet body、shape 和 joint。
3. 地形链必须是“主线程快照 -> builder 纯数值计划 -> 物理线程原生对象”。builder 不得
   持有 `Level`、`Chunk`、`BlockState` 或实体引用。
4. 物理线程不得直接读取 Minecraft 可变世界或实体状态；事件若需要改世界必须排回主线程。
5. 机构移除顺序必须是：停止新任务 -> 物理线程禁用/移除 joint -> 移除 body -> 清理
   owner 和缓存。关闭必须幂等，区块和 Level 卸载不能留下幽灵 body。
6. 不得把地形未 ready 处理成永久运动学车体或永久清零速度。等待策略必须保留机构
   所有权和已知动量，并在地形可用后恢复同一动力学系统。

### 1.5 验收与调试

1. 不通过放宽阈值、直接 `setPos`、人工抬升、永久上升力、清零水平速度或加大全局阻尼
   掩盖问题。
2. 每次修复只改变一个物理环节；先跑纯 JVM/原生测试，再跑单车 GameTest，再进入
   实机调试。
3. 自动测试通过不等于实机通过；每台车必须在计划规定的暂停点由用户检查。
4. 调试日志有明确样本上限，验证完成后删除逐帧日志；最终仓库不保留运行目录和日志。
5. 必须完成当前阶段，才允许进入下一阶段。阶段划分和完成条件以
   [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) 中该阶段的退出条件为准。退出条件未全部满足时，
   不得开始下一阶段的实施，也不得把下一阶段标成进行中。当前阶段内的修复、测试和文档同步，
   不属于进入下一阶段。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 高度场 | 从脱离世界引用的地形快照生成的、带有效性和表面类别的局部支撑表面数据 |
| 原始表面 | 未平滑的真实 voxel 碰撞外表面，用于门控、障碍判断和高度场构建 |
| 平滑表面 | 在有效表面内按受限向下规则得到的高度、法线和接触查询结果 |
| 支撑判定 | 判断履带板/车体某个碰撞形状是否与高度场表面接触，以及接触点、法线和侵入量 |
| 结构障碍 | 侧壁、天花板、实体和不可转换的高墙等非地面支撑碰撞 |
| 导动轮 | 不接收驱动、不承载独立悬挂的前/后端导向轮；是否参与张紧由数据声明 |
| 主动轮 | 接收通用轮带耦合驱动的轮，通常也承担一端的履带包络约束 |
| 负重轮 | 通过独立悬挂承载车体重量的道路轮 |
| 批准 | 某个车型的模型、几何、机构、测试和人工实机检查均满足阶段退出条件 |

## 3. 明确撤销的旧方案

- 按车长自适应坡长：**撤销，不得重新加入当前计划**。
- 固定 `RUN_BLOCKS` 的 TerrainSlopePlanner 楔面：**撤销为履带支撑方案**。
- 探针扫掠承载、高度场仅作探针 fallback：**撤销**。
- 只改车体接触法线、调用 `setNormalWorldOnB` 或额外向上施力的爬坡辅助：**撤销**。当前调用点仍在，见接线清单，不得写成已经删除。
- 预处理履带轨迹和预处理悬挂高度作为物理来源：**撤销**。
