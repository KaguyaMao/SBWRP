# 履带车辆测试与验收矩阵

更新时间：2026-10-19

## 1. 证据等级

| 等级 | 含义 |
|---|---|
| T0 | 纯数据/几何/单位测试，不创建 Minecraft 世界 |
| T1 | 原生 Bullet 独立机构测试，不读取 Level |
| T2 | Spark/KaguyaPyCore 地形和线程 GameTest |
| T3 | SBW 单车服务端 GameTest |
| T4 | 客户端/网络/渲染烟测 |
| T5 | 用户实机调试确认 |

只有用户在游戏中确认对应车型和场景后，该场景才可标记为“实机通过”。P0–P3 的证据确认不是实机通过。未写入 [`ACCEPTANCE_LIMITS.md`](ACCEPTANCE_LIMITS.md) 的数字不能当作通过阈值。

## 2. 高度场矩阵

| 用例 | 期望 | 最低等级 |
|---|---|---|
| 平面石块 | 高度场有效，履带板和车体静载稳定 | T1/T2 |
| 真实斜坡 | 接触高度和法线连续，载荷由高度场进入履带链 | T1/T3 |
| 一格高度差 | 只有满足有效表面门控时可通过 | T2/T3 |
| 连续一格楼梯 | 每级逐步更新高度场接触；无固定楔面或人工抬升 | T3 |
| 两格墙 | 高度场不生成有效支撑过渡，车辆被阻挡 | T2/T3 |
| 洞/空气 | 返回无效，不形成伪支撑 | T1/T2 |
| 未加载区块 | 等待或无支撑，不猜测地面 | T2 |
| 桥面/桥下 | 选择正确表面层，不能穿层承载 | T0/T2 |
| 硬软边界 | 不跨材质错误平滑，摩擦类别正确 | T0/T1 |
| 方块挖除 | revision 更新，旧支撑在规定窗口失效 | T2/T3 |
| section 边界 | 高度和法线不跳变，旧计划不会覆盖新计划 | T1/T2 |

## 3. 机构矩阵

| 用例 | 期望 |
|---|---|
| 单负重轮 | 静载约束、自由滚动、悬挂平动独立 |
| 单侧闭链 | 销到销和 hinge frame 误差不超过已冻结的 `pinClosureError`；未冻结时只记录测量，不标通过 |
| 双侧闭链 | 左右机构互不串扰，车体质量和载荷预算一致 |
| 导动轮 | 不被错误地当成负重轮；张紧自由度可解释 |
| 主动轮 | 通用耦合有反作用、有最大力矩、有滑移读数 |
| 落地 | 高度场接触先建立，不能依赖旧探针托车 |
| 一侧悬空 | 另一侧承载，车体姿态由 Bullet 求解 |
| 外部冲量 | 机构保留真实惯性和约束，不直接校姿态 |
| 关闭/卸载 | joint/body 按顺序清理，无幽灵对象 |

## 4. 99A T3 场景

1. 平地放置并静置至少 600 个物理子步。
2. 前进、倒车、释放油门、制动。
3. 原地左转、原地右转、行进左转、行进右转。
4. 真实斜坡上下行。
5. 一格高差、连续三阶楼梯、两格墙拒绝。
6. 一侧挖空、两侧挖空、车辆跨越局部洞。
7. 区块加载/卸载、地形 revision 更新、外部冲量。
8. 车辆移除、重载、Level 卸载和重新放置。

所有场景必须记录：高度场版本、有效支撑点数、每个板/轮的接触状态、车体速度、
角速度、悬挂行程、驱动目标/实际速度、接触载荷、物理子步耗时。

## 5. 实机暂停点

### A：静态机构

- 导轮和负重轮高度是否符合数据；
- 板销是否落在轮包络外；
- 板链是否有可见开口、穿轮或侧向漂移；
- 静置时车体、负重轮和履带板是否都承载合理。

### B：操控

- 左右差速方向；
- 加速和倒车是否有突跳；
- 刹车和释放油门是否抽搐；
- 原地转向是否围绕合理瞬时中心。

### C：地形

- 高度场接触可视化与可见方块是否合理；
- 单阶、楼梯、斜坡、两格墙和洞的边界；
- 没有旧楔面、探针或人工抬升支撑。

### D：长期和性能

- 单车长时间驾驶；
- 4 台活动车；
- 区块边界、睡眠唤醒、地形更新；
- 客户端渲染、网络延迟和资源占用。

## 6. 失败记录格式

失败不得只写“卡住/抖动”。至少记录：车型、数据/模型哈希、seed、位置、场景、
高度场 revision、支撑表面命中、结构障碍命中、板/轮数量、质量、悬挂力、驱动力、
车体速度/角速度、耗时和最小复现步骤。
